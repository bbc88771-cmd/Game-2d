# Sunset of the World — порт на Unity

Перенос игры «Некий» (веб-версия в корне репозитория) на **Unity 2022.3 LTS** / C#.
Лежит здесь, в папке `unity/`, чтобы не мешать веб-версии.

## Что уже перенесено (фаза 1 — ядро, проверено)

Модуль `Assets/Sunset/` (отдельная сборка `Sunset`, ни от чего не зависит, кроме
TextMeshPro/UGUI):

| Файл | Что это |
|------|---------|
| `Core/NekoBrain.cs` | «Мозг» диалога: классификация ввода, ~37 тем лексикона мира, внутримировой редирект (вопросы вне мира возвращаются к игре), конкретные ответы о игроке (город/время/система), шкалы доверия/тьмы, настроение, путь к концовке, анти-повтор (без повтора подряд) |
| `Core/NekoState.cs` | Состояние «Некого» и отношений + `PlayerProbe` (скан игрока). Сериализуемо |
| `Core/LobbyGate.cs` | Разблокировка локаций в лобби и условие старта (выбранную локацию должны открыть все) |
| `Core/SunsetSave.cs` | Сохранение в `PlayerPrefs` (JsonUtility) |
| `Data/GameLocations.cs` | 5 локаций-островов |
| `Tests/*` | EditMode-тесты (NUnit): классификация, редирект, лексикон, self-ответы, анти-повтор, настроение/концовка, лобби-гейт |

Логика — чистый C# без зависимостей от сцены. Перед коммитом собрана компилятором
Mono и прогнана отдельным харнессом — все проверки зелёные.

## Как открыть

1. Unity Hub → **Add → Add project from disk** → выбрать папку `unity/`.
2. Открыть (Unity подтянет пакеты, создаст `Library/`).
3. **Window → General → Test Runner → EditMode → Run All** — прогнать тесты «мозга» и лобби.

## Фаза 2 — UI (в работе)

Готов **играбельный экран диалога**:
- `UI/SunsetDialogue.cs` — строит из кода Canvas, прокручиваемый TMP-чат, поле
  ввода и кнопку; печатает ответы «Некого» по буквам; спрашивает имя; реагирует
  на тон (mood tint); сохраняет состояние в PlayerPrefs. Подставляет данные
  игрока (часовой пояс/ОС/время) в `PlayerProbe` для конкретных ответов.
- `Editor/SunsetSceneBuilder.cs` — меню **Sunset → Build Dialogue Scene**:
  собирает сцену одним кликом.

### Как запустить диалог
1. Меню **Sunset → Build Dialogue Scene**.
2. Если текст не виден — **Window → TextMeshPro → Import TMP Essential Resources**.
3. **Play** — печатай «Некому», он отвечает строго в рамках мира.

## Фаза 3 — катсцена (готово)

Перенесена **вступительная катсцена** (4 нарративных слайда «как раскололся мир»):

- `Data/CutsceneData.cs` — чистые данные слайдов (4 слайда, текстовые биты, вариант
  Ken Burns, частота «колокола», флаг «голос Некого»). Длительности слайдов
  распределяются пропорционально числу символов, минимум 8000 мс на слайд — как в
  веб-версии.
- `UI/SunsetCutscene.cs` — строит UI из кода: полноэкранный кадр с эффектом
  Ken Burns (наезд/отъезд), поднимающиеся угольки, белая вспышка на смене кадра,
  текстовые биты с плавным появлением, кнопка «пропустить», финальное затемнение.
  Событие `Finished` — для связки со следующей сценой.
- `Tests/CutsceneDataTests.cs` — EditMode-тесты данных (4 слайда, непустые биты,
  «голос Некого» только на финальном слайде, пропорции/минимум длительностей).
- `Editor/SunsetSceneBuilder.cs` — пункт меню **Sunset → Build Cutscene Scene**.

Фоновые спрайты ищутся в `Resources/Sunset/` (`background`, `loc_dead`, `loc_magic`).
Без них кадры заливаются тёмным цветом — катсцена остаётся проходимой без ассетов.
Финальный слайд — чёрный космос с красным «голосом Некого».

### Как запустить катсцену
1. Меню **Sunset → Build Cutscene Scene**.
2. При необходимости — **Window → TextMeshPro → Import TMP Essential Resources**.
3. **Play** — посмотри вступление (кнопка «пропустить ▸» ускоряет).

## Фаза 4 — главное меню (готово)

Перенесено **главное меню** с фоном, логотипом и колонкой кнопок слева:

- `Data/GameDifficulties.cs` — 5 уровней сложности (порт DIFFICULTIES).
- `Core/MenuPresence.cs` — реплики «Некого» в меню (приветствие по тому, как игрок
  ушёл и сколько не был; реплика «зависания»). Чистые функции.
- `Core/MenuJournal.cs` — записи дневника; «Некий» дописывает и правит их с ростом
  «тьмы»/визитов. Детерминировано по seed.
- `UI/SunsetMainMenu.cs` — строит UI из кода: фон+логотип, кнопки (Новая игра,
  Продолжить, Создать лобби, Ввести код, Настройки, Дневник, Выход), кнопка модов,
  присутствие «Некого», модальные окна (настройки со слайдерами/дропдаунами/
  тумблером, дневник, моды, выход).
- `Tests/MenuTests.cs` — EditMode-тесты присутствия, настроек, сложностей, дневника.
- `Editor` — пункт меню **Sunset → Build Main Menu Scene**.

Фон и логотип ищутся в `Resources/Sunset/` (`menu_bg`, `logo`). Без них фон будет
тёмным, а заголовок — текстом. Кнопки «Новая игра»/лобби пока показывают заглушку-
модалку (как в веб-прототипе) — сцены связываются отдельной фазой.

### Как запустить меню
1. Меню **Sunset → Build Main Menu Scene**.
2. При необходимости — **Window → TextMeshPro → Import TMP Essential Resources**.
3. **Play**.

## Фаза 5 — лобби (готово)

Перенесено **лобби** с каруселью локаций и гейтом старта:

- `Core/LobbyState.cs` — модель лобби (режим хост/гость, код, игроки до 5, выбранная
  локация, сложность); карусель с клампом, проверка старта через `LobbyGate`.
- `Core/LobbyCode.cs` — генерация/валидация кодов лобби (RNG снаружи → тестируемо).
- `Data/GameMods.cs` — стартовый набор модов лобби.
- `UI/SunsetLobby.cs` — строит UI из кода: шапка с кодом, сетка игроков, выбор
  сложности (хост), список модов с тумблерами, карусель локаций (стрелки/точки,
  замок по прогрессу, счётчик), сообщение гейта, степпер прогресса (хост) и кнопка
  «Начать игру», заблокированная, пока локацию не открыли все. «Друзья» подключаются
  по таймеру со случайным прогрессом — наглядно показывает работу гейта.
- `Tests/LobbyStateTests.cs` — EditMode-тесты модели, кодов и гейта старта.
- `Editor` — пункт меню **Sunset → Build Lobby Scene**.

Картинки локаций ищутся в `Resources/Sunset/` (`loc_start`, `loc_snow`, `loc_dead`,
`loc_swamp`, `loc_magic`). Без них карточка тёмная — лобби остаётся рабочим.

### Как запустить лобби
1. Меню **Sunset → Build Lobby Scene**.
2. При необходимости — **Window → TextMeshPro → Import TMP Essential Resources**.
3. **Play** (на объекте `SunsetLobby` можно переключить `isHost`/`simulateJoins`).

## Фаза 7 — красный код + скан игрока (готово)

- `Core/CodeStream.cs` — генератор «красного кода» (глифы + сегменты soul.bind/

- `Core/PlayerScan.cs` — «досье» игрока (имя/время/откуда/система/экран/язык/ядра),

- Интеграция в `UI/SunsetDialogue.cs`: фон диалога приоткрыт, код виден позади чата,

- `Editor` — демо **Sunset → Build Red Code Scene**.

## Фаза 8 — чат лобби + шёпоты «Некого» (готово)

- `Data/LobbyChat.cs` — реплики чата: общие реплики «Некого» на сбор группы, личные
  шёпоты с подстановкой имён ({a}/{b}), приветствия и болтовня «друзей».
- `UI/SunsetLobby.cs` (расширен) — прокручиваемый чат с полем ввода; при подключении
  «друга» он здоровается, «Некий» бросает общую реплику (на первого) или личный шёпот
  (на следующих), затем вошедший добавляет болтовню. Игрок может писать сам.
- `Tests/LobbyChatTests.cs` — EditMode-тесты пулов и подстановки имён.

## Фаза 9 — связка сцен (готово)

Экраны соединены в единый поток игры:

- `UI/SceneFlow.cs` — переходы по именам сцен (`MainMenu`, `Dialogue`, `Difficulty`,
  `Cutscene`, `Lobby`, `HeroSelect`, `World`). Если сцены нет в Build Settings — переход
  не падает, а пишет подсказку (отдельные сцены остаются запускаемыми по одной).
- `UI/SunsetDifficultySelect.cs` — экран выбора сложности новой игры (порт
  chooseDifficulty): 5 вариантов с описанием, выбор сохраняется в настройки.
- `UI/SunsetWorldStub.cs` — экран входа в мир «Стартовый остров» (порт startWorldStub):
  сводка имя/герой/сложность + прогресс секретки. Место будущего геймплея.
- Поток: **MainMenu** → «Новая игра» → **Dialogue** (интро «Некого» + красный код) →
  «далее ▸» → **Difficulty** (выбор сложности) → **Cutscene** → **HeroSelect** →
  **World** («Стартовый остров») → меню; **MainMenu** → «Создать лобби/Ввести код» →
  **Lobby** → «Начать игру» → **Cutscene** → **HeroSelect** → **World**. Кнопки «назад»
  ведут в меню. «Продолжить» в меню открывается после первого выбора героя.
- `Editor` — **Sunset → Build All Scenes**: собирает все 7 сцен и прописывает их в
  Build Settings (точка входа — `MainMenu`).

### Как запустить всю игру
1. Меню **Sunset → Build All Scenes**.
2. При необходимости — **Window → TextMeshPro → Import TMP Essential Resources**.
3. Открой сцену `Assets/Sunset/Scenes/MainMenu.unity` и нажми **Play**.

## Фаза 10 — процедурное аудио (готово)

Звук синтезируется в рантайме, без звуковых ассетов — как в веб-версии (там был
WebAudio-граф):

- `Core/AudioSynth.cs` — чистый синтез сэмплов: эмбиент-дрон (пила 55 Гц + синус
  82.4 Гц + шум, ФНЧ и медленный LFO), «колокол» (синус с атакой и экспоненциальным
  спадом) и «бип» сканера/печати. Возвращает массивы [-1, 1].
- `UI/SunsetAudio.cs` — оборачивает синтез в `AudioClip`: петля эмбиента с плавным
  входом/выходом, `Bell(freq)` и `Tick()` через `PlayOneShot`. Громкость — из настроек.
- Интеграция: катсцена включает приглушённый дрон и бьёт в «колокол» на смене кадра
  (частоты заложены в `CutsceneData`); диалог даёт «бип» сканера в момент скана.
- `Tests/AudioSynthTests.cs` — EditMode-тесты длины, диапазона и формы огибающих.

Озвучка-нарратив (mp3) в репозитории отсутствовала и в веб-версии (был только
процедурный звук + таймаут-заглушка), поэтому не переносится.

Паритет с веб-прототипом достигнут. Не переносится только сам геймплей мира
(движение/сбор/стройка/бой) — он и в вебе заглушка (`startWorldStub`).

## Графика (перенесена)

Все картинки из веб-версии лежат в `Assets/Resources/Sunset/` и грузятся кодом через
`Resources.Load<Sprite>`:

- `menu_bg`, `logo` — фон и логотип меню;
- `background` — первый слайд катсцены;
- `loc_start`/`loc_snow`/`loc_dead`/`loc_swamp`/`loc_magic` — острова (карусель лобби и
  слайды катсцены);
- `hero_tessi`/`hero_amira`/`hero_swordsman`/`hero_kaijo`/`hero_walter` — портреты.

SVG из веба растрированы в PNG (Unity не читает SVG «из коробки»); растровые (`*.jpg`,
`logo.png`) скопированы как есть. У каждого файла есть `.meta` с типом **Sprite**, чтобы
картинки грузились независимо от режима проекта (2D/3D). Заменить арт — просто положи
файл с тем же именем.

## Строительство (крафт построек)

По ТЗ: меню крафтов → выбор постройки → установка призраком в удобное место →
табличка с ресурсами → заполнение ячеек → анимация постройки.

- `Core/ResourceId.cs`, `Core/Inventory.cs` — ресурсы (древесина/камень/ветки/глина)
  и запас игрока.
- `Core/BuildRecipes.cs` — постройки и стоимость. Дубовый дом по ТЗ: 500 древесины,
  250 камня, 150 веток, 100 глины (+ изба, лавка, кузница, амбар; спрайты — дома-ассеты).
- `Core/ConstructionSite.cs` — учёт внесённых ресурсов против требуемых, готовность.
- `Game/BuildingGhost.cs` — полупрозрачный призрак установки (зелёный/красный по месту).
- `Game/ConstructionSiteView.cs` — площадка: недострой + табличка с ячейками-полосками,
  внесение ресурсов, анимация постройки + коллайдер готового дома.
- `Game/BuildController.cs` — меню крафтов, режим установки, HUD ресурсов, внесение.
- На острове: ресурсные ноды (по цвету), **C** — меню, **ЛКМ** поставить, **ПКМ/Esc**
  отмена, **E** внести ресурсы у площадки, **R** — выдать ресурсы (демо).
- `Tests/BuildingTests.cs` — инвентарь, рецепты, стройплощадка.

## Дневник — «невидимый геймдизайн»

Дневник героя переработан по дизайн-документу: он меняется вместе с игроком и
**намекает на концовку, не говоря прямо**.

- `Core/DiaryEntries.cs` — пулы записей: повседневные (с рисунками), бои (с добротой),
  намёки на «Некого», сомнения, тёплая/холодная/средняя ветка, мультиплеер, крипи
  (мягкие/сильные), особые редкие, записи под каждого героя (Тесси/Амира/Кайджо/Уолтер/
  Сэм-мечник), записи по островам (газ/тьма/высота/загадки) с ветками.
- `Core/Diary.cs` — сборка дневника по состоянию/герою: тон смещается по пути к
  концовке; **«Некий» дописывает** (3 уровня по тьме) и **правит старые записи**
  («Я не доверяю ему» → «Я доверяю ему», «я» → «мы») с припиской; изредка — крипи-
  записи; рисунки «портятся» (трещина/зубы) на тёмном пути. Детерминировано по seed.
- `UI/SunsetMainMenu` — дневник в меню рисуется по типам записей: рука «Некого»
  (✎, красная), крипи (красная курсивом), правки (помечены «изменено» + приписка),
  цвет всех записей теплеет/холоднеет по пути. Под каждого героя — свои записи.
- `Tests/DiaryTests.cs` — тон/уровни/правки/крипи/герои/детерминизм.

Старый `MenuJournal` заменён на `Diary`.

## Характер «Некого» и пути к концовке

По дизайн-документу «Некий» — **нейтральный** («никакой»): не плохой и не хороший, не
натравливает игроков друг на друга напрямую, может незаметно что-то проявлять или
поддержать. Его общение **смещается в зависимости от того, к какой концовке ведут
поступки игрока**: тёмные дела → он темнее (ведёт к разрушению), светлые → мягче.

- `Core/NekoLines.cs` — реплики по характеру/пути: общие (ломка 4-й стены), плохой/
  средний/хороший путь, тёплые, поддержка (светлая/грустная), мультиплеер
  (наблюдательные/командные — без натравливания), «двойные реплики» (тёплое → тревожный
  хвост), финалы по концовке.
- `Core/NekoPath.cs` — оценка пути (`good`/`middle`/`bad`/`drift`) по поступкам
  (`kind`/`cruel`/`dark`), «темнота» тона 0..1, `RecordChoice(good/bad)` для геймплейных
  выборов, финальная фраза.
- `Core/NekoVoice.cs` — подбор реплик по пути: спонтанные, поддержка, двойные,
  мультиплеер, финал; анти-повтор.
- `UI/NekoPresence.cs` (расширен) — реплики берутся из `NekoVoice` (по пути), цвет
  смещается по «темноте», иногда — «двойная реплика»; `Support()` после ошибок,
  `NoteDeed(good/bad)` сдвигает путь.
- На острове: **H** — поддержка, **G/B** — добрый/злой поступок (видно смену тона).
- `Tests/NekoPathVoiceTests.cs` — путь, тон, подбор реплик, финал.

## Общение с «Неким» — в игре, не в интро

По дизайну основной разговор с «Неким» идёт **во время игры**, а не в интро/лобби.
В интро он лишь узнаёт имя + пара реплик («я тебя вижу») и сам отсылает разговор в мир.

- `Core/NekoAmbient.cs` — что и когда «Некий» говорит в игре: спонтанные реплики по
  тону отношений и реплики по триггерам события (`night`, `wounded`, `resource_low`,
  `discovery`, `boss`, `build`), анти-повтор, **большие случайные паузы** (2.5–6 мин),
  чтобы не приставать и чтобы игрок успевал о нём забыть. Чистая логика, тесты.
- `UI/NekoPresence.cs` — ненавязчивый показ реплик «шёпотом» в углу: плавное
  появление/угасание, не перехватывает ввод. API `Trigger("night")` для событий и
  `Say(line)` для произвольной реплики. Повесь на объект игровой сцены.
- В сцене мира (`SunsetWorldStub`) присутствие уже подключено; клавиши **1–6** —
  демо-триггеры событий.
- `Tests/NekoAmbientTests.cs` — тоны, триггеры, анти-повтор, границы пауз.

## Прототип стартового острова (геймплей, вид сверху)

Первый игровой срез — не порт, а новая разработка. Построен модульно, чтобы
карту/персонажей/физику можно было менять по отдельности:

- `Core/Movement2D.cs` — чистая математика движения (нормализация диагонали), тесты.
- `Game/PlayerController2D.cs` — управление героем на `Rigidbody2D` (WASD/стрелки),
  параметры в инспекторе; графика-спрайт заменяема.
- `Game/CameraFollow2D.cs` — камера-следование с рамкой острова.
- `Game/EnemyStub.cs` — враг-преследователь (заглушка ИИ) на том же `Movement2D`.
- `Game/Pickup.cs` — подбираемый предмет (триггер при входе игрока).
- `Game/SunsetIsland.cs` — собирает сцену из кода: фон-остров (спрайт `loc_start`),
  границы, игрок, предметы, враг, камера, HUD и присутствие «Некого». Триггеры
  событий (`discovery`/`boss`/`wounded`) уже подключены к репликам «Некого».
- `Tests/Movement2DTests.cs` — EditMode-тесты движения.

Карта первой локации — большой летающий остров (`Resources/Sunset/island_start`,
вырезан из арта, фон-пустота прозрачный). Силуэт острова запечён в
`Core/IslandStartShape` (нормализованный контур + проверка «точка на земле»):
по нему строится `EdgeCollider2D`-граница (в пустоту не уйдёшь), а предметы/враг/дома
ставятся только на сушу. Временная графика персонажа/врага/предметов генерируется из
кода. Это «швы» для замены: арт/карту/героя/физику меняем по частям. Управление:
**WASD/стрелки**, **Esc** — в меню.

На острове расставлены **дома-ассеты** из `Resources/Sunset/` (`house_tower`,
`house_market`, `house_barn`, `house_smithy`, `house_porch`, `house_wood` — нарезаны
из присланного листа, фон сделан прозрачным). У каждого — коллайдер у основания.
Раскладку домов см. `SunsetIsland.HouseLayout`; добавить/заменить дом — положить
PNG в `Resources/Sunset/` и вписать строку в раскладку.

Поток: после выбора героя и экрана **World** («Стартовый остров») кнопка
**«Войти в мир →»** загружает сцену **Island**. Сборка: **Sunset → Build Island Scene**
(или **Build All Scenes** — остров включён, всего 8 сцен).

UI строится из кода (как в `SceneBuilder` соседнего проекта), чтобы не хранить
хрупкие `.unity`/`.prefab`.
